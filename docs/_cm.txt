ITEM 4 - DUPLICATE LEAKAGE (the big one)
NEU-CLS and NEU-DET are the SAME 1800 source photographs. eval/check_duplicates.py
finds 1045 cross-set pairs with pHash==0 AND dHash==0 (bit-identical), 7701
same-label pairs within threshold 6. File numbering gives it away: Cr_1.bmp vs
crazing_1.jpg, Pa_101.bmp vs patches_101.jpg. Our '3600-image' training set was
each photo twice, and a per-row split could put twins either side of the
boundary.

eval/splits.py now deduplicates to 1800 unique images (keeping the DET copy, since
inference runs on DET captures) and splits by identity GROUP:
  train=1138 val=310 test=621
  group overlap {'train&val': 0, 'train&test': 0, 'val&test': 0} -> CLEAN
Headline: 93.80% -> 92.75%. Leak was worth 0.3-0.7 points, but the number is now
defensible. The 13389 cross-label pairs are pHash collisions, not contradictory
labels, so identity is keyed on class+source index and hashing only VERIFIES.

ITEM 3 - CALIBRATION LEAKAGE
Temperature was fitted on the split used to report ECE, so ECE was optimistic by
construction. Now: weights on train, temperature on VALIDATION, reported on TEST.
ECE on test 0.0886 -> 0.0338 (T=0.75).

Triage now reported with the context it needs. Sensitivity 1.0000 is meaningless
alone, so alongside it: auto_pass_precision 1.000 (nothing auto-passed was
defective), auto_pass_rate 7.1%, clean auto-released 54.3%, auto-escalate 38.0%,
human review 51.0%. Sensitivity is 1.0000 at every threshold 0.50-0.95, so the
threshold buys automation, not safety - which is the honest reading.
